# CIFAR-10 Image Classification with Vision Transformer

[Portfolio Page](https://app.notion.com/p/3e968564df5a81de83eded127aa1047f)

Fine-tuned the pretrained Vision Transformer (ViT) `google/vit-base-patch16-224-in21k` on CIFAR-10, comparing classification accuracy and training cost across two fine-tuning settings.

## Approach

**Technologies:** Python, PyTorch, Torchvision, Hugging Face Transformers.

### 1. Data preparation

CIFAR-10 provides 50,000 training images and a separate 10,000-image test partition. The training script uses a seeded split (seed 54321) of the training partition into **45,000 training** and **5,000 validation** images.

- **Input processing:** Resize each 32×32 image to **224×224** and normalize using the pretrained model's image processor statistics.
- **Training augmentation:** Apply random horizontal flips and random crops with 16-pixel padding.
- **Validation processing:** Use a separate dataset instance with deterministic resize and normalization, without random augmentation.

### 2. Model and fine-tuning

The pipeline loads `google/vit-base-patch16-224-in21k` with Hugging Face's `ViTForImageClassification`. Its classification head is configured for **10 CIFAR-10 classes**. The `ignore_mismatched_sizes=True` option allows a new classification head to be initialized when its dimensions differ from the pretrained model.

The training loop processes batches of **16** with Adam (learning rate **3e-5**) and a **cosine learning-rate scheduler** with no warmup. Each step computes the model's supervised classification loss, updates the weights through backpropagation, and advances the scheduler.

After each epoch, the model switches to evaluation mode and computes validation accuracy by comparing the highest-logit predicted class (`argmax`) with each ground-truth label. Model weights are saved at `runs/vit_cifar10/epoch_<n>.pth` for every epoch.

### 3. Experiment configuration and evaluation

Two fine-tuning settings were compared with weight decay **5e-5**: **Setting #1** used one epoch, while **Setting #2** used three epochs. The included YAML config specifies Setting #2.

The separate evaluation script loads a specified checkpoint and measures accuracy on the **official CIFAR-10 test partition** using deterministic resize and normalization. The results table below reports validation, not test, accuracy.

## Results

| Setting | Epochs | Weight Decay | Validation Accuracy | Training Time |
|---|---:|---:|---:|---:|
| #1 | 1 | 5e-5 | 98.35% | 16.28 min |
| #2 | 3 | 5e-5 | 98.75% | 52.20 min |

Setting #2 improved validation accuracy by **0.40 percentage points**, while training took approximately **3.2 times longer**. Both settings used the same learning rate and weight decay, allowing a comparison across different epoch counts.

## Usage

Install dependencies:

```bash
pip install -r requirements.txt
```

Train:

```bash
python -m scripts.train --config config/vit_cifar10.yaml
```

Evaluate a saved checkpoint on the official CIFAR-10 test split:

```bash
python -m scripts.evaluate --config config/vit_cifar10.yaml --checkpoint runs/vit_cifar10/epoch_3.pth
```

The command uses a checkpoint generated by the training run. CIFAR-10, the pretrained model, and its image processor are downloaded on first use unless already cached.

## Limitations

The validation preprocessing was corrected to exclude random augmentation; the reported validation scores were recorded before this change. The pipeline saves a checkpoint at each epoch rather than automatically choosing the best model. Comparisons with other projects require matching evaluation splits and protocols.
